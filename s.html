S: Single Responsibility Principle

El Principio de Responsabilidad Única establece que una clase debe tener una sola razón para cambiar, es decir, debe encargarse de una única responsabilidad dentro del sistema. Cuando una clase mezcla varias tareas, como validar datos, guardar en base de datos y enviar correos, cualquier cambio en una de ellas puede romper las demás.

Aplicarlo produce clases pequeñas, cohesivas y fáciles de probar y mantener. En Spring esto se refleja al separar controladores, servicios y repositorios, cada uno con un propósito claro.
